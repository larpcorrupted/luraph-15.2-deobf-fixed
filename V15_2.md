# Luraph v15.2 (work in progress)

> Notes for the v15.2 work in this repo. Same rules as CLAUDE.md: a reference,
> not a changelog; keep it lean. The v15 plugin (`deobf/obfuscators/luraph_v15/`,
> LURAPH.md) is the base; this file lists only what differs in v15.2.

## Status

Nothing lifts yet. The v15 plugin detects the sample as `luraph_v15` (1.00), runs
the VM chunk and captures protos, but (1) the script spins in a loop after the
Path2D probe block and (2) the v15.2 lifter path still needs runtime validation.
`devirt.py` now has an initial captured-scope path for the nested v15.2 maker
(see "Lifter progress" below); it is not yet confirmed to produce a lift.

## Sample

- `sample.luau` (1,053,055 bytes): header `-- This file was protected using Luraph
  Obfuscator v15.2`, a `getgenv().SCRIPT_KEY = ...` line added by the owner, then
  `return setmetatable({[99]=buffer.writeu32, ...}):A()(...)` with a 988 KB
  `LPH...` payload in one long string and ~64 KB of VM object before it.
  Luraph loadstrings a 238,585-byte VM chunk (`\0CHUNK`), which holds 17 dispatch loops.
- `sample_src.luau`: 150-line fly script. **Not verified to be the source of
  `sample.luau`**: 5 KB vs 1 MB doesn't fit, and no fly behaviour shows in the trace
  (it never gets that far). Needs `sample_fly_obf.luau` (that source, obfuscated with
  the same options) as a trusted pair. Record the Luraph options used.

## Shape differences from v15

- Four VM implementations in the chunk (v15: usually two): dispatchers 0-3, 4-9,
  10-12, 13-16 (`vmmap.find_dispatchers` order). The first has an extra nesting level.
- Closure maker: v15 is `function(e, proto, upvals)` with `S,h = n, function(...)`.
  v15.2 is three levels: outer `function(t,W,m,a,X,V,E,E,c,k,_,R,Y,F)` (14 params: VM
  object `t`, per-proto opcode/operand arrays such as `F`, `X`, `_`, `Y`, `a`, `R`, `k`;
  prologue `local C,y,A,... = t[7],t.ZQ,...`) returns the maker `function(Z,Z,Z,J,i,U)`
  (4-6 params, repeated names, per-closure **numbers**: initial pc / state seeds) which
  `return function(...)` the interpreter directly (no assignment).
- So the proto key is the opcode array the dispatcher indexes (`vmmap._return_key`), not a maker
  parameter. 15 distinct arrays = 15 protos in the aborted run of the last VM.
- Handler shapes look like v15's (`g[Y[W]]=t[F[W]]`, `W=if g[X[W]]<=F[W]then W else Y[W]`,
  range-XOR decryptors that rewrite their own operands and `pc -= 1`).

## What the code does for v15.2 (`vmmap.py`, `driver.py`, `envlog.luau`)

- `maker_info` recognises `return function(...)`; key from `_return_key`; captures include
  the enclosing function's locals (`_scope_decls`; of repeated parameter names only the last
  is visible), and the maker's own prologue reads.
- `driver.patch_entries` rewrites `return function...end` into
  `__MK[1]=function...end; <hooks>; return __MK[1]` (table operations only, no locals:
  Luraph's stack-depth probe). `__MK` lives in `envlog.luau`.
- Entry hooks (`closure_entries`) use the same key (first dispatcher of a closure wins).
- Verified: the patched chunk parses (`luau-ast`), the hooks run (15 makers, all tables),
  `protos.json` is ~2 MB instead of 77 bytes.
- Not handled: the first VM (extra nesting level, the loader's).

## What doesn't work

1. **Endless loop after the Path2D block** (`aborted: endless loop in the script's own code`).
   A real loop (period 107 instructions, 94 pcs, nested short loops, calls through the VM
   object, no environment access). Not the decoder's length (watchdog at 600 checks =
   ~600M steps still aborts), not time (`os.clock`/`tick` x1000 via `--cfg prelude` changes
   nothing). Likely an environment answer that differs from real Roblox in a check v15.2
   added (LURAPH.md "Environment facts": any divergence gives a wrong key). The proxy trace shows
   `Vector2.new(a, b, c)` with three float arguments right before the stall. Next: run the sample
   once with `--studio` in real Studio and diff the Path2D/Random/library probes.
2. **Lifter scope capture.** The original error was `Unsupported: unbound local C@0,159280`.
   The first captured-scope change got past `C`, but the next run stopped at
   `unbound local U@0,159465`. The follow-up narrows a second issue in `vmmap._captures`:
   duplicate spellings were all discarded, even when the maker hook could resolve the innermost
   visible declaration. Capture metadata now carries declaration identities as well as names,
   keeps the last visible binding for v15.2's outer-to-inner maker scope, and restores only that
   AST declaration in `ProtoLifter.maker_scope`. The conservative v15 capture rule remains
   unchanged. **This refinement still needs a Codespaces run; it is not yet confirmed to clear U.**
   Further v15.2 child-maker calling conventions may be a separate blocker.

## Reproduce

```
./setup.sh
python3 deobf/deob.py sample.luau --debug --timeout 120
python3 deobf/obfuscators/luraph_v15/devirt.py sample.luau output/sample.protos.json \
    --chunk output/sample.chunk_*.luau --all out.luau       # offline lift, shows the traceback
```

`optrace.py` only patches the main script's loop heads; for the VM chunk patch the chunk text with
`optrace.patch_heads` and pass it through `harness.build_harness(main, cfg, {chunk_key: patched})`.
